# Merchant Referral Program in ahjoor-payments

## Overview

ahjoor-payments includes a merchant referral program that lets an existing approved merchant earn a commission when they introduce a new merchant to the platform. Once a referral is registered, every payment fee generated by the referred merchant automatically accrues a portion of that fee to the referring merchant's pending balance. The referrer can claim the accrued balance at any time, subject to a configurable commission window that caps how long accrual continues after the referral was made.

The feature is implemented in `contracts/ahjoor-payments/src/lib.rs` and covered by `contracts/ahjoor-payments/src/test_referral.rs`.

## Configuring referral terms

```rust
set_referral_config(env, admin, commission_bps, window_ledgers)
```

Only the contract admin can call this. It sets two global parameters:

- **`commission_bps`** — the percentage of each referred merchant's payment fee that flows to the referrer, expressed in basis points (100 bps = 1%). Setting this to `0` disables commission accrual entirely.
- **`window_ledgers`** — the number of ledgers after registration during which accrual is active. Set to `0` to allow indefinite accrual.

Both values are stored in instance-level storage and take effect immediately for all future accrual events.

## Registering a referral

```rust
register_referral(env, referrer, referred_merchant)
```

The referrer authorizes the call. The contract validates:

1. The referrer is an approved merchant.
2. The `referred_merchant` address does not already have a merchant record.

On success, a `ReferralRecord` is written for `referred_merchant`:

```
ReferralRecord {
    referrer,
    registered_at_ledger,  // current ledger sequence
    window_ledgers,        // snapshot of the global window at registration time
}
```

A `ReferralRegistered` event is emitted. The window snapshot is taken at registration time, so later changes to the global `window_ledgers` do not retroactively alter existing referrals.

## How commission accrues

Commission is accrued internally each time a referred merchant's payment is finalized. The internal function `accrue_referral_commission` is called with `fee_amount` (the protocol fee collected from the payment):

1. Looks up the `ReferralRecord` for the merchant. If none exists, returns immediately.
2. Checks whether the commission window has expired:
   ```
   current_ledger > registered_at_ledger + window_ledgers
   ```
   When `window_ledgers == 0`, the check is skipped and accrual never expires.
3. Reads the global `commission_bps`. If it is `0`, returns immediately.
4. Computes `commission = fee_amount * commission_bps / 10_000`.
5. Adds `commission` to the referrer's `PendingCommission` balance and to their `TotalEarnedCommission` lifetime counter.

The referrer does not need to take any action for commission to accumulate.

## Claiming commission

```rust
claim_referral_commission(env, referrer, token)
```

The referrer authorizes the call. The contract:

1. Reads the referrer's pending commission balance. Panics with `NoCommissionToClaim` if it is zero.
2. Resets the pending balance to `0`.
3. Adds the claimed amount to the referrer's `TotalClaimedCommission` lifetime counter.
4. Transfers the pending amount in `token` from the contract to the referrer.

A `CommissionClaimed` event is emitted.

## Querying referral data

- `get_referral_record(env, referred_merchant) -> Option<ReferralRecord>` — returns the referral record for the given merchant, or `None` if they were not referred.
- `get_pending_commission(env, referrer) -> i128` — returns the referrer's current unclaimed balance.
- `get_referral_commission_summary(env, referrer) -> (i128, i128)` — returns `(total_earned, total_claimed)`. Both default to `0` for addresses with no referral activity.

## Storage keys

- `ReferralRecord(Address)` — persistent referral record keyed by the referred merchant's address.
- `PendingCommission(Address)` — persistent pending commission balance for a referrer.
- `TotalEarnedCommission(Address)` — persistent lifetime earned total for a referrer.
- `TotalClaimedCommission(Address)` — persistent lifetime claimed total for a referrer.
- `ReferralCommissionBps` — instance-level global commission rate.
- `ReferralWindowLedgers` — instance-level global window duration.

## Events

- `ReferralRegistered { referrer, referred_merchant }` — emitted when a referral is registered.
- `CommissionClaimed { referrer, amount }` — emitted when a referrer claims their balance.

## Test coverage

Tests are in `contracts/ahjoor-payments/src/test_referral.rs`:

- Commission accrues correctly across multiple payments.
- Window expiry stops further accrual while leaving previously accrued amounts claimable.
- Successful claim transfers tokens and resets the pending balance.
- Registering the same referred merchant twice is rejected.
- A zero `commission_bps` config produces no accrual.
- `get_referral_commission_summary` returns both lifetime counters correctly.
